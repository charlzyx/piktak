WHY PIK.TAK

One local service should not require a whole VPN.

PIK.TAK started as a way to use DSH and PiAgent from a phone. It connects only the services you choose, through a Relay you control.

WORKS TODAY

Bridge an existing local service.

Run piktakd next to any HTTP, WebSocket, or TCP service. The application does not need to know PIK.TAK exists.

BUILT TOWARD

Pairing and transport for local applications.

Native Hosts and Clients can later share identity, service discovery, capabilities, and tunnels.

FIRST APPLICATION

Designed for more than DSH.

QUESTIONS

Is PIK.TAK a VPN?

No. It connects selected services instead of joining entire devices or networks.

Is it only for Agents?

No. DSH and PiAgent inspired it, but any suitable HTTP, WebSocket, or TCP service can connect.

Why not cloudflared?

cloudflared is the mature choice for putting a service behind Cloudflare. PIK.TAK is developing a Relay-independent pairing and transport protocol, with Cloudflare as one backend.

Does PIK.TAK run a public cloud?

No. Deploy the Worker in your Cloudflare account or run the Go Relay yourself.

常见问题

PIK.TAK 是 VPN 吗？

不是。它只连接选中的服务，不会把整台设备或整个网络接进来。

只能用于 Agent 吗？

不是。DSH 和 PiAgent 是起点，合适的 HTTP、WebSocket 或 TCP 服务都可以接入。

为什么不用 cloudflared？

如果只需要把一个服务接入 Cloudflare，cloudflared 更成熟。PIK.TAK 想做的是不绑定中继的配对和传输协议，Cloudflare 只是其中一种后端。

PIK.TAK 提供公共云吗？

不提供。你需要把 Worker 部署在自己的 Cloudflare 账号中，或者自己运行 Go 中继。
